# 데모 진행 가이드

`python demo.py` 한 줄로 도는 것을 **5분 안에 설명하기 위한 문서.**
터미널 출력의 각 블록이 어디서 나온 것인지만 짚는다.

---

## 1. 한 문장

> AWS 계정을 훑어 **ISMS-P 1.2.1 자산관리대장의 재료가 될 JSON**을 만든다.
> 자동으로 못 채우는 칸은 비워두지 않고 **"누가 / 왜 / 어떻게"**를 실어 보낸다.

---

## 2. 전체 흐름

```
demo_env.py          moto 안에 가짜 AWS 계정을 만든다 (실계정 아님)
    │                일부러 흠 있는 환경 — 태그 없는 서버, 미연결 볼륨, 미암호화 버킷
    ▼
collector/collect.py   AWS 응답을 손대지 않고 통째로 저장
    │                  ├─ session.py    계정→리전→서비스 순회, 페이지네이션
    │                  ├─ safe_call.py  예외·빈 응답을 상태 표지로 정규화
    │                  └─ services/*.py 서비스별 API 호출 (ec2 rds s3 backup security)
    ▼
snapshots/raw/{run_id}/{계정}/{리전}/{서비스}.json      ← 원본. 증적이자 재추출 원천
    │
    │  ★ 여기서부터 AWS에 접속하지 않는다. 로컬 파일만 읽는다
    ▼
collector/extract.py   config/extract_map.yaml 선언대로 필드를 뽑는다
    │                  1패스 자산 레코드 생성 → 2패스 조인(볼륨→인스턴스, SG 규칙)
    ▼
collector/manual.py    "담당자가 채워야 할 것"을 계산해 덧붙인다
    │                  config/manual_items.yaml 기준
    ▼
snapshots/normalized/{run_id}/assets.json               ← 담당 B 인계물
output/수기입력_템플릿.xlsx  /  output/iam_policy.json   ← 담당자·계정관리자용
```

**설정 3개가 동작을 결정한다. 코드가 아니다.**

| 파일 | 정하는 것 |
|---|---|
| `config/extract_map.yaml` | 원본의 어느 경로 → 계약의 어느 필드 |
| `config/isms_asset_types.yaml` | 자산유형 11종과 유형별 요구 항목 |
| `config/manual_items.yaml` | 수집 불가 항목과 담당자 작업 지시 |

## 3. 터미널 출력이 어디서 나오는가

| 화면 블록 | 만든 곳 | 읽는 법 |
|---|---|---|
| `[1/4] 가짜 환경` | `demo_env.py`의 `describe()` | **심은 것의 목록.** 실제 생성 코드는 같은 파일 `build()` |
| `[2/4] collect` 요약 | `collect.py` | 덤프 파일 수 = 리전 × 리전서비스 + 전역서비스 |
| `수집 중 만난 상태` | `safe_call.py`가 남긴 `__status__` 집계 | 세 상태를 절대 안 섞는다 |
| `데모 표시 필터` | `demo.py` | moto 산출물 제외. **원본 JSON은 그대로** |
| `[자동 수집]` | `extract.py` | 자산유형별 건수 |
| `0건 — 수집했으나 없음` | `extract.py` + `manual.py` | **확인했더니 없다** |
| `0건 — 수집기가 없어` | 〃 | **확인하지 않았다** |
| `태그만 달면 자동화됨` | `manual.py` | 한 번 투자하면 끝나는 일 |
| `수기 등재 필요 — 영구` | 〃 | 계속 드는 비용 |
| `권한 부족·조회 실패` | 〃 | **자산 부재가 아니다** |
| `리전별 분포` | `demo.py` | 미사용 리전 방치 = 자산 누락 1순위 |
| `[4/4] 산출물` | `demo.py` | 파일 4종 |

## 4. "6대 심었는데 왜 7건?" — 숫자 대조

시연 중 가장 먼저 나올 질문이다. **차이는 전부 설명된다.**

| 심은 것 (`[1/4]`) | 나온 것 (`[자동 수집]`) | 차이의 정체 |
|---|---|---|
| 서버 6대 | **서버 7건** | 다른 리전에 심은 EC2 1대 |
| 볼륨 4개 | **정보 15건** | 볼륨 11 + 버킷 4.<br>볼륨 11 = 직접 만든 4 + **인스턴스 7대의 루트 볼륨 7** |
| 버킷 3개 | 〃 | 다른 리전 버킷 1개 포함 = 4 |
| DB 2대 | **데이터(DBMS) 2건** | 일치 |
| 스냅샷 2개 | **가상자원 2건** | 일치 |
| 보안그룹 2개 | **네트워크장비 16건** | SG 4(직접 2 + **기본 SG 2**) + 서브넷 10 + VPC 2<br>서브넷·VPC는 **AWS가 계정에 기본 제공** |

> **이게 오히려 이 도구의 요점이다.**
> 관리자가 명시적으로 만들지 않은 자산(루트 볼륨, 기본 VPC·서브넷)까지 목록에 들어온다.
> 수기 관리로는 절대 안 잡히는 것들이고, **"관리자가 존재조차 모르는 자산"**이 정확히 이 범주다.

## 5. 시연에서 짚을 세 가지

### ① 세 종류의 "0건"이 다르다 — 이 도구의 핵심 주장

```
[0건 — 수집했으나 자산이 없음]   보안시스템 0건 ← 침입차단·탐지·방지 미확인
[0건 — 수집기가 없어]            PC / 설비 / 시설
[권한 부족·조회 실패]            infra_facts.backup_exists 24건
```

| 표시 | 뜻 | 심사에서 |
|---|---|---|
| 수집했으나 0건 | **확인했더니 정말 없다** | 통제 부재. 결함 소지 (`결함사례 1`) |
| 수집기가 없어 0건 | **확인하지 않았다** | 아무 말도 못 한다 |
| 조회 실패 | **못 읽었다** | 자산 부재가 아니다 |

셋을 같은 `0`으로 적으면 대장이 거짓이 된다.
데모 환경이 보안시스템을 **일부러 비워둔** 이유가 첫 번째를 보여주기 위해서다.

### ② 값이 없으면 이유가 같이 실린다

```json
"owner_dept":    { "value": null, "reason": "TAG_ABSENT",
                   "hint": "OwnerDept 태그를 달면 다음 실행부터 자동 수집됩니다" }
"exposure_path": { "value": null, "reason": "OUT_OF_SCOPE",
                   "hint": "ELB·CloudFront 수집기가 있어야 확정됩니다" }
```

**"모른다"와 "없다"를 구분하는 것이 전부다.**
권한이 없어 암호화를 못 읽은 걸 "미암호화"로 적으면 기밀성 등급이 통째로 틀린다.

### ③ 못 채우는 칸에 담당자와 조치가 붙는다

```
[태그만 달면 자동화됨]
  · 관리부서·관리실무자·관리책임자   38건 (90%)  → 각 자산 운영 부서
[수기 등재 필요 — 영구]
  · 내부정보 유출통제 시스템       현재 0건 등재  → 정보보안팀
```

**둘은 완전히 다른 일이다.** 앞은 태그 한 번으로 38건이 해결되고, 뒤는 매번 손으로 관리한다.
섞어 보여주면 담당자가 무엇부터 할지 못 정한다. `현재 0건 등재`는 수기 등재 행의 수이지
AWS 수집 건수가 아니다.

## 6. B가 받아갈 것

| 파일 | 용도 |
|---|---|
| `snapshots/normalized/{run_id}/assets.json` | **인계물.** 자산 + 사유 + `infra_facts` |
| `config/isms_asset_types.yaml` | 자산유형별 요구 항목 |
| `config/manual_items.yaml` | 수집 불가 항목 정의 |
| `docs/contract.md` | **필드 명세.** 이거 하나로 코드를 짤 수 있다 |

**B가 반드시 알아야 할 3가지**

1. `PERMISSION_DENIED` · `COLLECT_ERROR` · `OUT_OF_SCOPE`를 **자산 부재로 읽지 말 것**
   (`meta.reason_codes_not_absence`에 명시)
2. `NOT_APPLICABLE`은 갭으로 세지 말 것 — 개념이 없는 것이지 미확인이 아니다
3. `encryption_at_rest`에 `SSE-KMS-CMK`는 나오지 않는다 → **룰 C-06 사용 불가**
   (KMS 수집기가 있어야 CMK 판별 가능)

## 7. 시연 중 나올 만한 질문

**Q. 실제 AWS 계정에 붙는 건가?**
아니다. `moto`가 boto3 호출을 가로챈다. 자격증명을 가짜로 덮어쓰고,
수집 계정이 목 계정(`123456789012`)이 아니면 즉시 중단한다.
실계정에 붙는 명령은 `python -m collector collect` 하나뿐이다.

**Q. 스냅샷 2337건은 뭔가?**
moto가 `OwnerIds=['self']` 필터를 구현하지 않아 Amazon·Canonical 소유 스냅샷을
돌려준다. 실계정에서는 안 나온다. 데모는 **몇 건을 왜 뺐는지 밝히면서** 거르고,
원본 `assets.json`에는 그대로 남긴다.

**Q. `backup_exists` 조회 실패 24건은 도구 버그인가?**
moto가 `list_protected_resources`를 구현하지 않았다. 실계정에서는 정상 조회된다.
**이걸 `false`로 적으면 "백업 없음"이 되어 무결성 등급이 틀리므로** `COLLECT_ERROR`로 남긴다.

**Q. 왜 collect와 extract를 나눴나?**
수집 시점에 필드를 골라 버리면 B가 필드를 추가 요청할 때 AWS를 다시 불러야 한다.
전 리전 순회는 수 분이 걸리고 그 사이 리소스가 바뀌어 비교 기준선이 흔들린다.
원본을 두면 **`extract_map.yaml` 한 줄 + 재추출**로 끝난다.

**Q. 등급은 왜 안 나오나?**
등급 산정은 담당 B 영역이다. 이 도구는 **판정하지 않고 사실만** 넘긴다.
`infra_facts` 17키가 B의 등급 룰 입력값이다.
